## 3. 关键差距(TOP 3)

### GAP-1: AI无态 → Agent无记忆(最严重)
- 竞品表现: 飞书aily有会话记忆+人格+主动推送; Notion AI有文档上下文
- TBH现状: 每次打开AI聊天都是空白,无法延续之前的分析和建议
- **量化差距**: 用户需重复描述上下文次数 TBH=3-5次 vs 竞品=0次
- **用户可感知度**: 极高 — 连续工作流断裂

### GAP-2: AI入口孤立 → 非嵌入式
- 竞品表现: 飞书多维表格AI侧边栏、Notion编辑器内AI、ClickUp任务上AI按钮
- TBH现状: AI是独立模块页面,需离开当前工作上下文切换到"AI"页面
- **量化差距**: AI使用路径 TBH=3-5跳 vs 竞品=1跳(原地触发)
- **用户可感知度**: 高 — 降低AI使用频率

### GAP-3: AI不可用 → 计费+容灾缺失
- 竞品表现: 全部有付费AI服务,且有fallback机制
- TBH现状: DeepSeek 402余额不足→AI完全不可用,无graceful degradation
- **量化差距**: AI可用率 TBH≈0%(缺余额) vs 竞品≈99.9%
- **用户可感知度**: 致命 — 核心差异化功能失效

## 4. 本周改进目标(最多2项)

### 改进1: AI记忆层 — 会话持久化(Priority: P0)
**目标**: AI聊天保持最近10条会话历史,重启后可恢复
**方案**: 使用localStorage存储最近的聊天会话(每用户最多5个),AI初始化时自动加载最近会话
**预期效果**: 重复描述上下文次数从3-5降至0-1
**验收**: 重开AI页面后能看到上次的对话,可继续提问

### 改进2: AI容灾增强 — 三层fallback强化(Priority: P1)
**目标**: 当DeepSeek不可用时,本地fallback提供有意义的响应(非通用模板)
**方案**: 扩展directLLMFallback的分析能力,针对TBH业务场景(OKR/复盘/风险/任务)提供结构化本地建议
**预期效果**: AI可用率从0%提升至100%(质量分层:云端>本地)
**验收**: API Key失效时,AI仍能给出结构化业务建议,且明确提示"本地模式"
